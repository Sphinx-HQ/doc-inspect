# Roadmap

A new phase lands roughly every 2–3 weeks, sized to the phase.

The toolkit reports facts and never decides. Every pixel of the demo UI should
be justifiable as presentation of facts. Production detection stays on
[WatchDoc](https://watchdoc.sphinxhq.com/?utm_source=oss&utm_medium=readme&utm_campaign=watchdoc-python).

## Now: Phases 0 and 1

Installable `watchdoc` package with `inspect()` (local facts) and a thin
`Client.check()` (one POST to WatchDoc's document-checks API). PDF Info + XMP
and image EXIF. One-page Flask demo. Synthetic samples.

## Phase 2: Polished UI

A design pass. The demo should be a clear, usable free document inspector.

- Tailwind and a component library other than DaisyUI, so the OSS UI is not a
  stripped clone of any hosted playground.
- Document viewer (pdf.js / image) with page navigation and zoom. Pure
  rendering: no overlays, no highlights.
- Facts panel with fixed groups (Metadata, Provenance, Structure, Fonts)
  that later phases slot into without a redesign.
- Locked cards for WatchDoc-only capabilities, designed in rather than bolted on.
- Dark mode, responsive layout, drag-and-drop batch upload, JSON export.

There will not be a version-diff view or a slider.

## Phase 3: Structural facts

- Incremental-save count by counting `%%EOF` markers (standard PDF behavior),
  plus per-save dates. Count and dates only: no version splitting, no text
  diff, no highlight artifacts.
- Trailer `/ID` original vs current, reported as a fact.
- "No Info dictionary and no XMP" reported as a fact.
- Fonts used per page, as a raw listing. No statistics or thresholds over that list.

## Phase 4: Standards-based provenance

- C2PA manifest presence, using public standards and existing open-source libraries.
- Publicly documented AI-generator metadata markers in PNG/JPEG.

Presence is reported as a fact.

## Phase 5: Hosted template match

`Client(api_key).match_template(file)` against a free WatchDoc endpoint (API key
from a WatchDoc account). Coarse result only: issuer and
`strong_match` / `weak_match` / `no_match`. A "Template match" card in the demo,
with copy: template match is not a fraud decision; run a full check for that.

Framed as powered by WatchDoc's hosted issuer reference bank. Uploads are
subject to WatchDoc's terms of service.

## Phase 6: Open benchmark

A public, reproducible benchmark for document tampering detection, hosted in
this repo or a sibling `*-bench` repo.

- Fully synthetic dataset generated by scripts: templated invoices, statements,
  and payslips plus scripted operations named at the level of "text edited via
  incremental save". Ground truth is known by construction. No real customer
  documents.
- Public train/test splits in the repo, plus a private held-out split used to
  verify leaderboard submissions.
- `bench.run(predictor)` where `predictor(file) -> {"tampered": bool}`; reports
  precision / recall / F1 overall and per category; writes a results JSON; PR-based
  leaderboard reproduced by CI.
- Day-one baselines: a naive rule over `inspect()`, the Phase 7 model, and
  WatchDoc via `Client.check`.
- Versioned dataset, changelog, and a guide for adding a tamper generator.

## Phase 7: Small tunable model

A model whose only inputs are Phase 1–4 `inspect()` facts (presence flags,
hashed producer/creator tokens, date deltas, save count, trailer ID mismatch,
XMP present, distinct-font count, C2PA / generator-marker presence). No visual
or document-content features.

scikit-learn logistic regression or a small gradient-boosted tree, CPU only.
Weights pretrained on the Phase 6 synthetic train split.

`model.fit(files, labels)`, `model.save()`, `model.explain(file)`. Output is
`{"tampered_probability": p}`: a probability from a model you can train, not a
verdict from WatchDoc. Docs will say: this is a baseline you own; for production
decisions use WatchDoc.

## Alongside: GitHub Action

A published Action that calls `POST /api/v1/document-checks/` (not local
`inspect()`). Inspect on your laptop with this toolkit; gate PRs with the hosted
Action.

## What we will not add

- Local detectors that produce verdicts, scores, or severity.
- Version-diff or a slider.
- A bring-your-own-LLM hook.
- Telemetry or phone-home from the package.
- Fabricated WatchDoc results in the demo. The commercial column renders only
  after a real API call.
